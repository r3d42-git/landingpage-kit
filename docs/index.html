Installation

Du brauchst einen Host mit laufendem Docker und dem Compose-Plug-in. Die Standardinstallation bindet beide Ports an Loopback. Sie lässt sich direkt auf dem Host nutzen. Für den Zugang von anderen Geräten findest du weiter unten die LAN-Einstellungen.

Die Befehle verwenden eine Unix-Shell. Auf Windows kannst du sie in WSL mit Docker-Anbindung ausführen.

1. Dateien vorbereiten

Lade das Installationspaket für Version 1.0.0 herunter. Entpacke es in einen neuen Ordner und öffne dort ein Terminal. Alle folgenden Compose-Befehle laufen im Ordner mit compose.yaml.

docker compose version
docker info
cp examples/dashboard.example.yaml dashboard.yaml

Die einzelnen YAML-Dateien und das vollständige Paket findest du auch unter Projektdateien. Das Offline-Handbuch im Paket öffnest du über docs/index.html.

Öffne dashboard.yaml in einem Texteditor. Passe Titel, Kategorien und Links an oder probiere das Beispiel unverändert aus. Behalte die eindeutigen IDs bei, wenn du bestehende Einträge weiterpflegst.

2. Startseite und Editor einrichten

docker compose pull
docker compose run --rm --no-deps -T landingpage python tools/configure.py init < dashboard.yaml
docker compose run --rm --no-deps landingpage python tools/configure.py password
docker compose up -d
docker compose ps

Wähle mindestens 16 Zeichen ohne Leerzeichen an Anfang oder Ende. Das Passwortwerkzeug fragt das Editorpasswort zweimal verdeckt ab und erzeugt für eine neue Installation auch das lokale TLS-Zertifikat. Verwahre das Passwort in deinem Passwortmanager. Die Initialisierung ist für einen neuen Datenstand vorgesehen.

3. Start und Anmeldung prüfen

Öffne auf demselben Rechner http://127.0.0.1:8080/. Unter Bearbeiten wechselst du zum HTTPS-Editor. Der HTTP-Port dient der Leseansicht. Der Editor verwendet ein Zertifikat einer eigens erzeugten lokalen Zertifizierungsstelle (CA). Exportiere ihr öffentliches Zertifikat auf dem Installationshost. Übertrage es auf vertrauenswürdigem Weg zu deinem Browser, vergleiche den SHA-256-Fingerabdruck der CA und hinterlege sie auf deinem Gerät als vertrauenswürdig. Mit curl kannst du das Zertifikat gezielt für einen Aufruf verwenden.

docker compose exec -T landingpage python tools/configure.py certificate > landingpage-local.crt
openssl x509 -in landingpage-local.crt -noout -fingerprint -sha256
curl --cacert landingpage-local.crt https://localhost:8443/
Zugriff im eigenen LAN einrichten

Wähle eine lokale Adresse des Hosts und einen Namen, den die Geräte im LAN dorthin auflösen. Ergänze die folgenden Variablen in der .env neben compose.yaml. Ersetze die Beispieladresse und den Namen durch deine eigenen Angaben. Ports müssen frei sein.

DASHBOARD_BIND=192.0.2.10
DASHBOARD_EDIT_HOST=dashboard.home.arpa
DASHBOARD_HTTP_PORT=8080
DASHBOARD_HTTPS_PORT=8443

Erzeuge auf dem Host das Zertifikat für deinen gewählten Namen, starte den Container mit den geänderten Einstellungen neu und exportiere die neu erzeugte CA wie oben. Aktualisiere die Vertrauenseinstellung deiner Geräte. Begrenze den Zugriff per Firewall auf das gewünschte Netz. Wer die Leseadresse erreicht, kann die veröffentlichten Kacheln und Messwerte einsehen.

docker compose run --rm --no-deps landingpage python tools/configure.py tls-local --host dashboard.home.arpa
docker compose up -d --force-recreate
Container-Image offline laden oder lokal bauen

Lade aus dem Release das Imagearchiv für die Architektur des Docker-Hosts herunter (amd64 für x86-64, arm64 für ARM64) und prüfe die SHA-256-Prüfsumme mit dem Eintrag in SHA256SUMS. Übertrage Archiv und Installationspaket zum Zielhost. Lade dort das Image und fahre beim Befehl configure.py init fort.

docker load -i landingpage-kit-linux-amd64.tar.gz

Für einen lokalen Build entpacke den Quellcode derselben Version. Baue mit beiden Compose-Dateien. Nutze bei den folgenden Compose-Befehlen ebenfalls beide -f-Optionen. Der Build benötigt Zugriff auf die Basisimages und Paketquellen.

docker compose -f compose.yaml -f deploy/compose.build.yaml build

Einrichtung mit einem Agenten

Kopiere den Auftrag in einen Agenten deiner Wahl, der auf deinem Zielsystem arbeiten darf. Ergänze den gewünschten Installationsort. Ein rein textbasierter Assistent kann dir die Schritte stattdessen zum Ausführen geben.

Installationsauftrag

Richte das Projekt https://github.com/r3d42-git/landingpage-kit nach dem zugehörigen Handbuch auf meinem Zielsystem ein. Prüfe Betriebssystem, Docker Compose, freie Ports und vorhandene Dateien. Kläre mit mir den Installationsordner und ob ich ausschließlich auf diesem Rechner oder auch im LAN zugreifen möchte. Verwende die offiziellen Dateien der gewählten Projektversion und die mitgelieferten neutralen Startdaten. Erhalte vorhandene Instanzen, verwende ausschließlich die vereinbarte Bind-Adresse und zeige keine Passwörter oder privaten Schlüssel im Chat. Richte den Dienst ein, prüfe den HTTP-Lesezugriff sowie den HTTPS-Editor und zeige mir die URLs, den Weg zur Passwortverwaltung und die Schritte für Sicherung und Update. Bitte mich bei einer erforderlichen lokalen Eingabe um die konkrete Aktion. Optionale Messquellen richten wir erst ein, wenn ich die gewünschten Ziele angegeben habe.

Erste Schritte im Editor

Mit der mitgelieferten Startdatei erscheint „Meine Startseite“. Unter Einstieg findest du das Handbuch und die „Beispielseite“. Eigene Dienste ist als leere Kategorie für deine ersten Einträge vorbereitet. Du kannst dort direkt eine Kachel anlegen oder eine zusätzliche Kategorie erstellen.

  1. Öffne die Startseite und wähle Bearbeiten. Der Browser öffnet die HTTPS-Anmeldung. Gib dein zuvor gewähltes Editorpasswort ein.
  2. Wähle am Ende der Seite Kategorie hinzufügen. Trage etwa „Werkzeuge“ ein, wähle ein Kategoriesymbol und bestätige mit Übernehmen.
  3. Öffne das Plus neben „Werkzeuge“. Trage als Name „Mein Wiki“ und als Adresse die URL deines Wikis ein. Ergänze eine Beschreibung und lasse Überwachung auf Nur Verknüpfung. Unter Weitere Optionen kannst du ein Schlagwort und das Verhalten beim Öffnen festlegen.
  4. Wähle Übernehmen und dann Vorschau. Mit Weiter bearbeiten kehrst du zum Entwurf zurück. Speichern veröffentlicht die Änderungen auf deiner Instanz für alle Geräte.

Über den Stift an einer Kachel änderst du ihren Inhalt. Verschieben öffnet die Auswahl für Kategorie und Position, auch auf dem Smartphone. Der Stift am Kategorienamen ändert Symbol, Namen und Reihenfolge. Den Seitentitel und Untertitel findest du im Bearbeitungsmodus unter Einstellungen.

In der Leseansicht filtert das Suchfeld die Dienste. Ein Klick auf einen Status in der Kopfzeile begrenzt die Ansicht auf passende Kacheln. Ein zweiter Klick hebt den Statusfilter auf.

Den passenden Kacheltyp wählen

Die Adresse öffnet das Ziel beim Anklicken. Das Feld Überwachung bestimmt, welche zusätzliche Information die Kachel anzeigt.

Nur Verknüpfung
Ein Lesezeichen für Wiki, Dokumentation oder Weboberfläche. Die Option Erreichbarkeit prüfen ruft die URL vom Server aus etwa alle fünf Minuten ab. Zwei aufeinanderfolgende Fehler melden einen Ausfall. Öffentliche HTTP(S)-Adressen auf Standardports sind möglich. Interne Ziele und abweichende Ports benötigen eine explizite Freigabe.
HTTP-Erreichbarkeit
Prüft eine freigegebene Webadresse. Wähle Adresse des Dienstes oder eine vorbereitete HTTP-Messquelle, wenn etwa der Klick zur Oberfläche und die Prüfung zu einem separaten Health-Endpunkt führen soll.
Pi-hole
Wähle eine Pi-hole-Quelle für DNS-Anfragen und blockierte Anfragen. Zusätzliche Werte kannst du auf der Kachel aufklappen. Der Adapter braucht Zugriff auf die passende Statistik-API.
NAS
Wähle eine Speicherquelle für tatsächlich gemessene Kapazität und Auslastung. Für ein NAS eignen sich ein lokaler Snapshot oder über Prometheus bereitgestellte SNMP-Speicherdaten.
Dienstmetriken
Zeigt benannte Messwerte einer Quelle. Geeignet für die aktiven Scrape-Ziele eines Prometheus-Servers, zwei TCP-Prüfungen eines Hosts oder eigene Werte aus einer Snapshot-Datei.
YouTube-Kanäle
Trage unter Kanal hinzufügen ein öffentliches @Handle, eine Kanal-ID oder eine Kanaladresse ein. Klicke auf Hinzufügen, anschließend auf Übernehmen und Speichern. Eine Kachel fasst bis zu zwölf Kanäle zusammen und zeigt neue Videos der letzten 24 Stunden sowie den jüngsten Upload. Hierfür ruft der Server öffentliche Feeds ab.

Eine Messquelle einrichten

Jede Quelle bekommt eine eindeutige id und einen sichtbaren Namen (label). kind wählt den Adapter, display_kind ordnet die Quelle dem passenden Kacheltyp im Editor zu. Verwalte deine Quellen in einer eigenen integrations.yaml. Kopiere dazu die Beispieldatei, passe die Werte an und importiere die gesamte gewünschte Quellenliste.

cp examples/integrations.example.yaml integrations.yaml

Für einen ersten Funktionstest enthält die Datei bereits HTTP-Status der Landingpage. Importiere sie mit den Befehlen aus Schritt 3 unten, füge eine Kachel mit Adresse /healthz hinzu und wähle HTTP-Erreichbarkeit → HTTP-Status der Landingpage. Nach dem Speichern prüft der Container seinen eigenen Statusendpunkt.

Beispiel A · HTTP-Status eines Dienstes

  1. Ermittle den Health-Endpunkt eines eigenen Dienstes. Das folgende Beispiel erwartet einen erfolgreichen JSON-Aufruf mit dem Feld status und dem Wert UP. Ersetze die Beispieldomain an beiden Stellen durch dein Ziel.
  2. Füge die Origin (Schema, Host und gegebenenfalls Port) und den Quelleneintrag in die bestehenden Listen ein. Eine leere Konfiguration kannst du so befüllen.
allowed_endpoints:
  - https://wiki.example.org
sources:
  - id: wiki-status
    label: Wiki-Status
    kind: http
    display_kind: http
    url: https://wiki.example.org/health
    expect_json:
      status: UP

Für eine reine HTTP-Statusprüfung entfällt expect_json. Standardmäßig gelten 200 und 204 als Erfolg.

  1. Speichere die Datei als integrations.yaml. Importiere sie, kontrolliere die verfügbaren Quellen und öffne anschließend den Editor neu.
docker compose run --rm --no-deps -T landingpage python tools/configure.py sources < integrations.yaml
docker compose exec -T landingpage python manage.py sources
  1. Öffne den Stift der Wiki-Kachel. Wähle HTTP-Erreichbarkeit → Messquelle → Wiki-Status, dann Übernehmen → Speichern. Nach dem ersten Abruf siehst du den gemessenen Zustand. Der Dienst muss aus dem Container per DNS und Netzwerk erreichbar sein.

Beispiel B · Speicherplatz vom Host anzeigen

Mit einem Snapshot gelangen auch Werte aus dem Betriebssystem in eine Kachel. Der mitgelieferte Sammler ermittelt den Speicherplatz des Dateisystems, das du mit --path auswählst. Führe ihn auf dem Host mit Python 3 aus. Die Messdatei wird für den Container nur lesbar eingebunden.

mkdir -p instance/metrics
python3 examples/write-disk-snapshot.py ./instance/metrics/disk-usage.json --path /
docker compose -f compose.yaml -f deploy/compose.metrics.yaml up -d

Verwende für den weiteren Betrieb dieselben Compose-Dateien, beispielsweise über COMPOSE_FILE=compose.yaml:deploy/compose.metrics.yaml in der .env auf einem Linux-Host. In der mitgelieferten integrations.example.yaml ist die passende Quelle bereits definiert. Falls du eine eigene Quellenliste verwendest, ergänze den folgenden Eintrag einmal unter sources.

  - id: disk-usage
    label: Speicherbelegung
    kind: snapshot
    display_kind: nas
    file: disk-usage.json
    max_age: 180
  1. Importiere die Quellen mit configure.py sources wie im HTTP-Beispiel. In der Ausgabe von manage.py sources muss die Quelle als nas erscheinen.
  2. Füge im Editor eine Kachel hinzu. Trage Name und Zieladresse ein, wähle NAS und unter Messquelle den Namen der Quelle. Klicke auf Übernehmen und Speichern.
  3. Für regelmäßige Messwerte plane den Python-Aufruf auf dem Host beispielsweise einmal pro Minute per Cron oder systemd-Timer ein. Verwende dabei absolute Pfade zu Python, Skript und Ausgabedatei. max_age: 180 markiert die Daten nach drei Minuten ohne neue Messung als veraltet.
Beispiel für einen minütlichen Cronjob

Ermittle die Pfade mit command -v python3 und pwd im Installationsordner. Öffne mit crontab -e die vorhandene Tabelle des Benutzers, der in das Messverzeichnis schreiben darf. Ergänze eine Zeile und ersetze die Beispielpfade durch deine eigenen. Prüfe nach zwei Minuten den Zeitstempel von disk-usage.json.

* * * * * /usr/bin/python3 /opt/landingpage-kit/examples/write-disk-snapshot.py /opt/landingpage-kit/instance/metrics/disk-usage.json --path /

Andere Sammler können dasselbe Format schreiben. observed_at ist die Messzeit in Unix-Sekunden, state einer der Werte ok, warning, down, unknown oder stale. metrics enthält Paare aus label und value. progress ist optional und liegt zwischen 0 und 100. Schreibe zunächst eine temporäre Datei und ersetze die Zieldatei anschließend atomar.

Weitere Adapter

TCP-Port und Host
tcp verwendet eine tcp://-URL mit explizitem Port. host benötigt zwei Einträge unter targets, jeweils mit label und url für denselben Host auf unterschiedlichen Ports. Gib jede Origin einzeln unter allowed_endpoints frei.
Pi-hole
kind: pihole liest die kompatible Statistik-API an der angegebenen url. Optional ergänzen blocking_url auf derselben Origin und eine lokale dns_file die Daten um Blockierungsstatus und DNS-Messung.
Prometheus und SNMP-Speicher
prometheus erwartet als url die Basisadresse. snmp_volume nutzt ebenfalls die Prometheus-Basisadresse, zusätzlich job, instance und den Wert von hrStorageDescr als volume. Der Exporter muss Größe, belegte Einheiten und Einheitengröße des ausgewählten Volumes liefern.
Vorhandene Host-Sammler
Die Werkzeuge unter tools/ können Checkmk-Livestatus, Proxmox-Messwerte oder Speicherbelegung über einen beschränkten SSH-Zugang lesen. Die verfügbaren Argumente zeigt python3 tools/collect_checkmk.py --help, python3 tools/platform_metrics.py --help bzw. python3 tools/collect_ssh_storage.py --help. Zugangsdaten, private Schlüssel und Monitoring-Berechtigungen verwaltest du auf dem Host.

Sicherung und Updates

Einträge und Logos exportieren

Speichere den Entwurf und öffne angemeldet Einstellungen → Datensicherung → Exportieren. Die ZIP-Datei enthält die gespeicherten Kategorien, Kacheln und lokalen Logos. Zum Einspielen wähle Wiederherstellen, öffne deine ZIP-Datei und bestätige den Austausch der aktuellen Inhalte. Sichere zuvor den aktuellen Stand.

umask 077
docker compose exec -T landingpage python manage.py backup > startseite.zip
docker compose exec -T landingpage python manage.py restore --confirm < startseite.zip

Die gesamte Instanz sichern und zurückholen

Das Compose-Volume dashboard-data enthält die SQLite-Datenbank, die aktiven Quellen, Startdaten, das Editorpasswort und den privaten TLS-Schlüssel. Sichere es konsistent bei gestopptem Dienst. Wähle für jede Sicherung einen neuen Dateinamen. Starte die App nach dem Export wieder und kontrolliere den Archivinhalt.

umask 077
docker compose stop landingpage
docker compose run --rm --no-deps -T landingpage tar -C /data -czf - . > volume-backup.tar.gz
docker compose start landingpage
tar -tzf volume-backup.tar.gz

Bewahre das Archiv zugriffsgeschützt und verschlüsselt auf. Sichere separat .env, benutzte YAML-Dateien, lokale Sammler, Zeitpläne und externe Messdaten. Notiere die eingesetzte Imageversion.

Teste die Wiederherstellung in einem neuen Installationsordner mit derselben Compose-Datei und Imageversion. Kopiere nur deine vertrauenswürdige Sicherung dorthin. Verwende einen neuen Compose-Projektnamen für ein eigenes Volume und freie Loopback-Ports. Prüfe vor dem Start die Bind-Adresse und ob der wiederhergestellte Zertifikatsname zum Editor passt.

docker compose -p landingpage-restore run --rm --no-deps -T landingpage tar -C /data -xzf - < volume-backup.tar.gz
DASHBOARD_BIND=127.0.0.1 DASHBOARD_HTTP_PORT=18080 DASHBOARD_HTTPS_PORT=18443 docker compose -p landingpage-restore up -d
docker compose -p landingpage-restore exec -T landingpage python manage.py show

Öffne die wiederhergestellte Ansicht auf Port 18080 und prüfe Kategorien, Logos und nach der Anmeldung auch die Bearbeitung. Mit docker compose -p landingpage-restore stop beendest du nur diese Testinstanz.

Passwort wechseln und Zertifikat erneuern

Setze ein neues Passwort auf dem Docker-Host und starte den Dienst neu, damit er es einliest. Dieser Weg funktioniert auch bei vergessenem Editorpasswort.

docker compose run --rm --no-deps landingpage python tools/configure.py password
docker compose restart landingpage

Das lokale Serverzertifikat gilt ein Jahr. Zur Erneuerung führe configure.py tls-local wie im LAN-Abschnitt mit allen benötigten --host-Angaben aus. Starte anschließend den Dienst neu und exportiere die neue CA für deine Geräte. Das Passwort bleibt dabei nutzbar.

Auf eine neue Version wechseln

  1. Sichere ZIP und Volume. Notiere den bisherigen Image-Tag. Prüfe die Versionshinweise.
  2. Übernimm die zur neuen Version gehörende Compose-Konfiguration in denselben Installationsordner. Erhalte deine .env, zusätzlichen Compose-Dateien und den Compose-Projektnamen. Ein abweichender Projektname kann ein neues Volume anlegen.
  3. Lade das gewünschte Image und erstelle den Dienst neu. Kontrolliere danach die Kacheln und den HTTPS-Editor.
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail 50 landingpage

Die Startseite später über YAML ändern

Die alternative Vorlage examples/dashboard-monitoring.example.yaml beschreibt ein vollständiges Dashboard mit den Quellen dashboard-health und disk-usage. Du kannst einzelne Kacheldefinitionen aus ihr in deine eigene YAML übernehmen.

Der Datenbestand lebt nach dem ersten Start in SQLite. Für eine bewusste Änderung über YAML vergleiche die gewünschte vollständige Startseite mit dem gespeicherten Stand. Prüfe auch die Einträge, die die Vorschau zur Entfernung vorsieht. Verwende beim Anwenden die gerade angezeigte Revision anstelle von N.

docker compose exec -T landingpage python tools/configure.py preview < dashboard.yaml
docker compose exec -T landingpage python tools/configure.py apply --revision N < dashboard.yaml

Bei einem Revisionskonflikt erstelle eine neue Vorschau und gleiche parallele Änderungen ab.

Fehler beheben

Die Seite lädt nicht

Führe im Installationsordner docker compose ps und docker compose logs --tail 50 landingpage aus. Prüfe belegte Hostports, die konfigurierte Bind-Adresse sowie HTTP bzw. HTTPS in der aufgerufenen Adresse. Bei Loopback-Bindung funktioniert der Zugriff direkt auf dem Host.

Der Editor öffnet die falsche Adresse oder meldet ein Zertifikatsproblem

Vergleiche Namen oder IP und HTTPS-Port des Links mit deiner Installation. Das Zertifikat muss zu dieser Adresse passen. Exportiere die aktuelle lokale CA wie im Installationsabschnitt. Vergleiche ihren SHA-256-Fingerabdruck über einen vertrauenswürdigen Zugang zum Host und prüfe, ob genau diese CA im Browser als vertrauenswürdig hinterlegt ist.

openssl x509 -in landingpage-local.crt -noout -fingerprint -sha256
Eine Messquelle fehlt oder ein Wert ist veraltet

Prüfe die Quellen-YAML, die Ausgabe von manage.py sources und den gewählten Kacheltyp. Eine HTTP-Freigabe muss exakt zur Ziel-Origin passen. Bei Snapshots müssen Dateiname, Leserechte und Zeitstempel stimmen. „Veraltet“ bedeutet, dass die letzte Messung ihr zulässiges Alter überschritten hat. Mit docker compose exec -T landingpage python manage.py status kannst du die Zustände prüfen.

Meine Änderungen sind nach dem Neuladen verschwunden

Übernehmen ändert den Entwurf. Erst Speichern schreibt ihn in die gemeinsame Datenbank. Meldet der Editor einen Versionskonflikt, notiere deine Änderungen, lade die aktuelle Fassung und übertrage sie erneut. Die Startdaten werden beim ersten Anlegen der Datenbank eingelesen.
